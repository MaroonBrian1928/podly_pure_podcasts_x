# antislop audit 001, 2026-09-23

Scope: `frontend/src` (React + Tailwind), branch `add-apprise` @ `d78abbf`.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## HIGH

1. **Dark mode contrast breaks where a color class has no override** (R-25, R-34).
   Dark mode is a ~420-line list of `html.dark [class~="…"] { … !important }` remaps in `src/index.css:192-502`. Any class missing from the list keeps its light value while its sibling gets remapped:
   - `components/config/tabs/CostsTab.tsx:483`: `bg-yellow-50` stays light, `text-yellow-800` becomes pale yellow. Pale text on a pale button.
   - `CostsTab.tsx:500`, `CostsTab.tsx:510`: `hover:bg-blue-100` unmapped, so hover shows light blue text on a light blue button.
   - `components/FeedDetail.tsx:748`: same with `hover:bg-indigo-100`.
   Fix: add the missing remaps, or switch these four elements to `dark:` variants (already used 146 times elsewhere).

2. **`text-gray-400` used as body text in light mode** (R-25). `#9ca3af` on white is about 2.5:1, under the 4.5:1 minimum. 34 uses, e.g. `FeedList.tsx:155` (empty-state hint), `LandingPage.tsx:203,214` (footer icons), plus the `—` cells in `LLMProcessingStats`/`ChapterProcessingStats`. `text-gray-500` passes.

3. **Two modals bypass `ModalShell`: no Escape, no dialog semantics** (R-26, R-32).
   `components/DiagnosticsModal.tsx:76` and `components/config/shared/EnvOverrideWarningModal.tsx:22` build their own overlay. `ModalShell` already handles Escape; reuse it.

4. **Dropdown menus don't close on Escape** (R-32). App mobile menu (`App.tsx`, "Toggle menu"), `HomePage.tsx:334`, `FeedDetail.tsx:869`. They close only on an outside click.

5. **Landing page pricing contradicts the billing page** (R-38, C-5).
   `LandingPage.tsx:141`: "choose number of podcasts ($1/pod/month)".
   `BillingPage.tsx:115`: "Get 10 feeds for a monthly price of your choice (min $X)".
   One of them is stale.

6. **Live tester counter has no loading or error state** (R-27). `LandingPage.tsx:15` uses `userCount ?? 0`, so while loading, or if `/landing/status` fails, the page shows a pulsing green "live" dot next to **"0 active testers"**. Hide the badge until the data arrives.

7. **Em dashes in UI text** (R-02).
   - Prose: `JobProgress.tsx:280,285` ("attempt 3 — backoff, retrying in…"), `JobsPage.tsx:517` ("…failed to parse — likely classifier miss.").
   - Empty-value placeholder: `utils/datetime.ts:20,28,46`, `AnimatedDuration.tsx:19`, and about 15 table cells in `CostsTab`, `JobsPage`, `LLMProcessingStats`, `ChapterProcessingStats`. This one is a common table convention. Your call: keep it (noted as an override) or switch to `–` / "n/a".

8. **Icon-only links have no accessible name** (C-4). Landing footer GitHub and Discord links (`LandingPage.tsx:199,210`) are bare SVGs. Add `aria-label`.

## MEDIUM

9. **Motion with no reduced-motion opt-out** (R-19). `index.css:568` covers modals, tabs and page transitions, but not:
   - `animate-digit-tick` (blur + overshoot bounce on every timer digit, `AnimatedDuration.tsx`)
   - `animate-progress-shimmer` (infinite, `JobProgress.tsx`)
   - the landing page's `animate-pulse` dot
   Add `motion-reduce:animate-none`, or add them to that media block.

10. **Rainbow gradient stat tiles** (R-01, R-29). `ChapterProcessingStats.tsx:271-296` and `LLMProcessingStats.tsx:375-396`: each metric gets its own `bg-gradient-to-br` hue (purple, green, red, indigo, blue). Green (kept) and red (removed) mean something. Purple, indigo and blue don't, and the gradient itself adds nothing. Use flat neutral tiles and keep color only for kept/removed.

11. **Uppercase wide-tracked section labels** (R-06). `LandingPage.tsx:127,139` ("LISTEN ANYWHERE", "GETTING STARTED") sit directly above content that already says the same thing. Minor.

## LOW

12. **Leftover Vite template CSS** (C-1). `App.css:17-51`: `.logo`, `logo-spin`, `.card`, `.read-the-docs` aren't used anywhere. `App.css` is also imported twice (`App.tsx:21`, `main.tsx:4`).

13. **CTA wording** (R-15). "Sign Up!" appears twice on the landing page (`:90`, `:168`) and both point at `/login`. The empty state says "Click "Add Feed" to get started." Something specific like "Request a tester slot" would fit the test-group framing better.

14. **Inconsistent wording** (`LandingPage.tsx:72`): `slotsRemaining === 1 ? 'slot' : 'spots'` shows "1 slot remaining" but "3 spots remaining".

15. **No design direction on record** (R-37, R-20). There's no `DESIGN.md`, and the UI is stock Tailwind gray plus `blue-600`. This is fine for a utility dashboard, but any landing page redesign needs direction first. It won't be fixed as part of this audit.

## Checked and clean

- No invented stats: the tester count comes from the live API.
- No testimonials, FAQ, logo bar, bento grid or fake terminal.
- Nav links all go to real routes or sections (`#how-it-works` exists).
- No Lucide or sparkle icon sets. The SVGs are inline and relevant.
- Wherever `outline-none` removes the focus outline, it's replaced by a `focus:ring-*` / `focus-visible:ring-*`.
- Glassmorphism is on one element only (the landing header). Shadows are limited to popovers and modals.
- `ModalShell` modals close on Escape.
